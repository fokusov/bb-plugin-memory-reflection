# Memory Reflection

Плагин анализирует завершённые потоки BB и предлагает короткие долговечные уроки для встроенного BB Memory. Задания и предложения хранятся в отдельной SQLite-базе плагина; исходный транскрипт в эту базу не копируется.

## Настройка

Автоматическая обработка выключена по умолчанию. В настройках плагина можно включить обработку при завершении хода или архивировании потока, автоматическое сохранение только явно запрошенных уроков и срок хранения результатов.

Обычные выводы остаются на review в панели **Memory Reflection**. Сохранение в глобальную память требует отдельного выбора **Сохранить глобально**. Запись в память проекта доступна только для проектов с локальным source на машине BB; глобальную запись можно сделать и для удалённого проекта.

## Команды

```text
bb memory-reflection status [--json]
bb memory-reflection reflect [thread-id] [--json]
bb memory-reflection list [--json]
bb memory-reflection approve <candidate-id> --scope project|global [--json]
bb memory-reflection reject <candidate-id> [--json]
bb memory-reflection retry <job-id> [--json]
```

`reflect` без ID использует поток, из которого вызвана команда. Автоматические события не воспроизводятся задним числом после перезагрузки плагина; для пропущенного потока можно запустить ручную рефлексию.

## Безопасность и устройство

- Очередь использует уникальный ключ по проекту, потоку, sequence снимка и версии правил. Фоновый worker использует lease и повторяет временные ошибки с задержкой. Чтение истории начинается с последней страницы, использует курсоры BB и учитывает только сообщения до sequence снимка. При устаревшем курсоре чтение один раз начинается заново.
- Для генерации создаётся скрытый worker в личном проекте BB с личным окружением. Задание и предложения сохраняют ID исходного проекта. В prompt передаются выбранные пользовательские и assistant-сообщения в пределах лимита; известные токены, ключи, адреса почты и телефоны редактируются. После получения результата временный поток архивируется, останавливается и удаляется.
- Режим разрешений временного обработчика выбирается из возможностей провайдера исходного треда: сначала `auto`, затем `accept-edits`, затем `full`. Провайдер с единственным режимом `full` получает полные разрешения, поэтому такой запуск пишется предупреждением в лог плагина. Обработчик не вызывает инструменты и не получает доступ к памяти.
- Worker возвращает строгий JSON. Сервер проверяет схему, ссылки на сообщения пользователя и признаки чувствительных данных. Его `explicit_remember` не является источником разрешения на запись: сервер сам проверяет исходное сообщение пользователя.
- Один прогон может предложить до 12 отдельных уроков. Повторно найденный в другом снимке того же треда урок отбрасывается по нормализованному отпечатку вида, имени и краткого описания; детали и доказательства остаются привязаны к сохранённому предложению.
- Автоматическая запись ограничена явной просьбой запомнить, confidence не ниже 0.9, локальным проектом и отсутствием результатов поиска по имени/теме. Совпадение блокирует запись; существующие записи не обновляются и не удаляются.
- Запись и поиск выполняются через публичные команды `bb memory search` и `bb memory add` без shell-интерпретатора. Данные проходят как отдельные аргументы процесса; CLI получает ID исходного проекта и потока, а записи помечаются тегом `auto-reflection`. Для проектной памяти CLI запускается с каталогом source проекта; глобальная запись не требует локального source.
- При удалении исходного потока незаписанные предложения и незавершённые задания очищаются. Завершённые предложения и задания удаляются политикой retention.
