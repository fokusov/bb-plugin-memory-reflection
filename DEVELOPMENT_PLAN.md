# План разработки Memory Reflection

## Цель

Обрабатывать завершённые потоки BB, предлагать короткие долговечные уроки и сохранять их в BB Memory только после проверки политики безопасности или явного подтверждения пользователя.

## Этапы

1. **Настройки и границы запуска** — выключить автоматизацию по умолчанию; отдельно управлять событиями завершения и архивации, авто-сохранением явных просьб, размером источника и сроком хранения.
2. **Надёжная очередь** — хранить задания и review-кандидатов в SQLite плагина; дедуплицировать по проекту, потоку, sequence снимка и версии правил; применять lease, ограниченные повторы и очистку при удалении источника.
3. **Генерация рефлексии** — читать ограниченный снимок завершённых сообщений, редактировать известные секреты и контактные данные, вызывать временный скрытый worker и удалять его после получения результата.
4. **Проверка уроков и запись** — валидировать структурированный JSON и ссылки на пользовательские сообщения; по умолчанию отправлять выводы на review; авто-сохранять только уроки с проверенной явной просьбой; перед записью искать возможные дубликаты и не перезаписывать существующие записи.
5. **Управление пользователем** — предоставить review-страницу, RPC и CLI для статуса, ручной постановки, подтверждения, отклонения и повторного запуска.
6. **Сборка и приёмка** — проверить TypeScript, собрать app/server bundles, загрузить локальный плагин и пройти изолированный сценарий от lifecycle-события до review-кандидата без записи в Memory.

## Критерии готовности

- Автоматическая обработка выключена после установки.
- Повтор одного и того же lifecycle-события для того же снимка не создаёт второе задание.
- Ошибки генерации можно повторить; lease и уникальные ключи защищают обработку при повторном запуске worker.
- Кандидат принимается только при валидной схеме и ссылках на сообщения пользователя.
- Обычные выводы требуют review; автоматическая запись ограничена явно запрошенными уроками и не заменяет существующие записи.
- Пользователь может сохранить урок в проектную или глобальную область только с явным выбором области.
- Сборка и загрузка плагина проходят, а очередь переводит тестовое завершённое событие в review без вызова реального LLM и без записи в BB Memory.

## Результат текущей реализации

- Этапы 1–5 реализованы в настройках, SQLite-хранилище, backend worker, CLI, RPC и app-панели.
- `npx tsc --noEmit` и `bb plugin build .` завершились успешно.
- Локальный плагин установлен и загружен; service очереди работает, app bundle совместим с текущим SDK.
- Изолированный SDK smoke подтвердил переход от `thread.idle` к `pending_review`; повторное событие для того же снимка создало одну задачу, кандидат без явного запроса не сохранялся.
- Сквозной вызов реального провайдера намеренно не запускался: smoke не отправлял содержимое пользовательского потока внешнему worker.
