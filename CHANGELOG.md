# Changelog

Эти версии фиксируют локальную разработку и выпуски плагина.

## 0.2.1

- Автосохранение стало осторожнее: автоматическая запись отменяется, если поиск в памяти нашёл любую похожую запись, а не только совпадение имени или описания. Такой урок остаётся на review с пометкой о возможном дубликате, и решение принимает пользователь. Ручное подтверждение по-прежнему блокируется только точным совпадением.

## 0.2.0

- Автосохранение по доверию: новая настройка (по умолчанию выключена) записывает в память проекта уроки с доверием не ниже порога, по умолчанию 90%. В глобальную память автосохранение не пишет — для неё остаётся явный выбор области.
- Действия по уроку стали видны в панели: включённый режим автосохранения описан в шапке страницы.

## 0.1.4

- Запись в память привязана к серверу, на котором работает плагин: `bb memory` запускается с `BB_SERVER_URL` этого сервера. Раньше в отдельном профиле команда наследовала адрес другого сервера и запись попадала в чужую память под несуществующий там проект.

## 0.1.3

- Ссылки на источники могут указывать на любое сообщение снимка, включая ответы assistant: подтверждение причины и результата обычно содержится именно там. Просьба «запомни» по-прежнему учитывается только в сообщении пользователя.
- Запрос к worker требует собственных доказательств на каждый урок и запрещает переиспользовать один общий кик-офф для нескольких уроков.
- Предпроверка дублей больше не сравнивает весь текст запроса: `bb memory search` ищет по любому слову, поэтому длинный запрос давал ложные конфликты. Дублем считается только совпадение имени или краткого описания.
- Провайдер без объявленных режимов разрешений (opencode2) получает worker без этого поля, а не ошибку задания.
- Ожидание временного обработчика увеличено до пяти минут: медленный провайдер больше не теряет задание на 120 секундах.

## 0.1.2

- Временный обработчик выбирает режим разрешений по объявленным возможностям провайдера исходного треда. Провайдер с единственным режимом `full` больше не роняет задание с ошибкой `Provider pi only supports full permission mode`; такой запуск отмечается предупреждением в логе плагина.
- Тест на выбор режима разрешений, на несколько уроков из одного снимка и на явную ошибку при неполном охвате истории.

## 0.1.1

- Чтение истории треда восстановлено: снимок начинается с последней страницы timeline, следует курсорам BB и учитывает только сообщения до sequence снимка. Устаревший курсор перезапускает чтение один раз.
- Временный обработчик снова запускается в личном проекте BB; после получения результата поток архивируется, останавливается и удаляется.
- Повтор проблемного задания в рабочей сборке вернул предложения на review.
- Добавлены тесты выбора ранних и поздних сообщений в пределах лимита, следования курсорам, перезапуска на устаревшем курсоре, редактирования длинных секретов и дедупликации повторного урока.
- Автоматическая обработка по-прежнему выключена по умолчанию; сохранение в память требует явного выбора области.

## 0.1.0

- Первая реализация: очередь заданий и review-предложений в SQLite плагина, ручной запуск, панель проверки, RPC и CLI.
- Ограниченный снимок завершённых сообщений с редактированием известных секретов и контактных данных.
- Проверка строгой схемы ответа и ссылок на сообщения пользователя; выводы по умолчанию отправляются на review.
- Автоматическое сохранение ограничено явной просьбой «запомни», confidence не ниже 0.9, локальным проектом и отсутствием найденного дубликата.
- Запись и поиск выполняются через публичные команды `bb memory search` и `bb memory add` без shell-интерпретатора.
